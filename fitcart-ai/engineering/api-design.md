# Engineering — API Design

REST + JSON, versioned under `/v1`. Async for AI jobs. OpenAPI auto-generated by FastAPI. All bodies validated by Pydantic.

## 1. Conventions
- Base: `/v1`. Auth: `Authorization: Bearer <jwt>`.
- Errors: RFC-7807-style `{type, title, status, detail, instance}`.
- Pagination: `?limit=&cursor=`. Idempotency-Key on mutating job creation.
- Timestamps ISO-8601 UTC.

## 2. Auth
| Method | Path | Body → Result |
|---|---|---|
| POST | `/v1/auth/register` | {email\|phone} → {user_id, otp_sent} |
| POST | `/v1/auth/verify` | {identifier, otp} → {access, refresh} |
| POST | `/v1/auth/login` | {identifier, otp\|social_token} → tokens |
| POST | `/v1/auth/refresh` | {refresh} → {access} |
| POST | `/v1/auth/logout` | — → 204 |

## 3. Users, profile, consent
| Method | Path | Notes |
|---|---|---|
| GET/PATCH | `/v1/users/me` | profile |
| GET | `/v1/users/me/consents` | list versioned consents |
| PUT | `/v1/users/me/consents` | grant/revoke {type, granted} |
| DELETE | `/v1/users/me` | DPDP erasure (async hard-delete job) |
| GET | `/v1/users/me/export` | DPDP data export |

## 4. Body profile & avatar (async)
| Method | Path | Notes |
|---|---|---|
| POST | `/v1/profiles/body/upload` | multipart images + {height_cm, weight_kg?} → {upload_id, validation} |
| POST | `/v1/profiles/body/generate` | {upload_id} → 202 {job_id} |
| GET | `/v1/profiles/body/avatar/{id}` | {smpl_ref, measurements, confidence, status} |
| DELETE | `/v1/profiles/body/{id}` | delete body data |

Validation response example:
```json
{ "ok": false, "issues": ["body_cropped","low_light"],
  "guidance": ["Step back so head-to-feet are visible","Move to brighter light"] }
```

## 6. Outfits & try-on (async)
| Method | Path | Notes |
|---|---|---|
| POST | `/v1/outfits` | {name, items[]} → outfit |
| GET/PATCH/DELETE | `/v1/outfits/{id}` | CRUD |
| POST | `/v1/tryon` | {avatar_id, items[], angles?, quality?} → 202 {job_id} (Idempotency-Key) |
| GET | `/v1/tryon/{job_id}` | {status, render_set[], fit_report?} |
| POST | `/v1/fit` | {avatar_id, product_id, size} → FitReport (sync or job) |
| POST | `/v1/outfits/{id}/score` | → OutfitScore |

Try-on result:
```json
{ "status":"done",
  "render_set":[{"angle":0,"url":"...","res":"1024"}, {"angle":45,"url":"..."}],
  "fit_report":{"fit_score":8.6,"confidence":0.82,"issues":["trousers may run long"]} }
```

## 7. Cart & handoff
| Method | Path | Notes |
|---|---|---|
| GET | `/v1/cart` | internal cart |
| POST | `/v1/cart/items` | {product_id, variant_id, store_id} |
| DELETE | `/v1/cart/items/{id}` | remove |
| POST | `/v1/cart/checkout` | → grouped deep-links per store (+affiliate) OR partner-sync where supported |

Checkout response:
```json
{ "groups":[
  {"store":"amazon","action":"deeplink","url":"https://...tag=fitcart-21"},
  {"store":"myntra","action":"deeplink","url":"https://..."},
  {"store":"partnerX","action":"cart_sync","status":"synced"} ] }
```

## 10. Versioning & deprecation
New breaking changes → `/v2`. Deprecations announced via response headers + docs. Contract tests guard adapter + AI-service schemas (`engineering/testing.md`).
